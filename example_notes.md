## 6. Linked List

- Reverse Linked List - Use two pointers: prev and curr. Initialize prev to None. For each node, first save curr.next, then reverse the link by setting curr.next = prev. After that, move both pointers one step forward (prev = curr and curr = next). Repeat until curr becomes None. prev will then point to the head of the reversed list.

**Dummy Node -** is often used to as a temporary placeholder so that you don't have to do special calculation for deciding the head of the result array. **Use a dummy node when the operation can potentially change or remove the head of the linked list.**

- Merge Two Sorted Linked Lists - Use two pointers, l1 and l2, to compare the current nodes of the two lists. Create a dummy node at the beginning to simplify handling the head of the merged list. At each step, attach the node with the smaller value to tail.next, then move both the corresponding list pointer (l1 or l2) and tail forward. Once one list is exhausted, attach the remaining nodes of the other list to tail.next.
- Linked List Cycle Detection - Uses the concept of Floyd cycle detection algo. fast reaches null if cycle does not exists, if cycle exists, fast and slow become same. Cycle is detected.

**Floyd hare and tortoise cycle detection algorithm** - The reason it works is -

1. No cycle case is trivial, fast will always reach the end of the linked list if it exists sooner than slow because it is moving at twice the speed.
2. If a cycle exists, fast and slow will eventually meet at the same node because once fast enters the cycle, both pointers are moving within the same loop. Since fast moves two steps at a time and slow moves one step at a time, the distance between them decreases by one node on every iteration, causing fast to catch up to slow.

- Reorder Linked List - Notice that the reordered list consists of two halves of the original list: the first half remains in its original order, while the second half appears in reverse order. From this observation, we know we first need to split the linked list into two halves. We use the fast and slow pointer technique because when fast reaches the end of the list, slow will be positioned just before the start of the second half. In other words, slow.next is the first node of the second half. We then reverse the second half and finally merge the two halves by alternating nodes from each list.
- Remove Nth Node From End of List - We use two pointers left and right with a dummy node before the head to handle the edge case where the head itself needs to be removed. We first move the right pointer n nodes ahead, creating a gap of n nodes between left and right. Then we move both pointers together until right reaches the end. At this point, left will be pointing to the node before the node that needs to be removed. We simply remove it by changing the link left.next = left.next.next and return dummy.next as the new head.
- Copy Linked List with Random Pointer - The main problem in solving this question is connecting the random pointer of a node to another node whose copy may not have been created yet. We solve this by making two passes through the linked list. In the first pass, we create a copy of every node and store the mapping from the original node to its copy in a hash map. In the second pass, we use this mapping to assign the next and random pointers of each copied node by looking up the copies of the original node's next and random pointers. Finally, we return hashmap[head], which is the head of the copied linked list.
- Find the Duplicate Number - Although the input is given as an array, we can treat it as a linked list where each value points to the next index. We then apply Floyd's Cycle Detection Algorithm to find the duplicate number. We initialize slow and fast pointers, where slow moves one step at a time and fast moves two steps at a time. If they meet, we know a cycle exists. To find the start of the cycle, we initialize another slow pointer at the beginning of the array while keeping the other pointer at the meeting point. Both pointers now move one step at a time, and the node where they meet is the start of the cycle, which is also the duplicate number.
- LRU Cache - The cache needs to support both get and put operations in O(1) time, so we combine a hash map and a doubly linked list. The hash map stores a mapping from each key to its corresponding node (key to node mapping), allowing constant-time lookup. The doubly linked list maintains the order of usage, where the node closest to left is the Least Recently Used (LRU) and the node closest to right is the Most Recently Used (MRU). We make two helper functions insert and remove to manipulate node position. Whenever a key is accessed or updated, we remove its node from its current position and insert it just before right, marking it as the most recently used. During a put, if the key already exists, we first remove its old node. We then create and insert the new node, and store it in the hash map. If the cache size exceeds the capacity, we evict the least recently used node (left.next) by removing it from the linked list and deleting its key from the hash map using del cache[lru.key]. Using the doubly linked list allows insertion and removal in O(1) time, while the hash map provides O(1) access to any node.

## 7. Binary Tree

Main traversal techniques are BFS and DFS. Both can be achieved iteratively or recursively.

DFS has three main types:
1. Preorder - Process root → left → right
2. Inorder - Process left → root → right
3. Postorder - Process left → right → root

- Invert Binary Tree - (Recursive) → We recursively swap the left and right child of every node in the tree. The base case is when the current node is None, in which case we simply return None. For each valid node, we first swap its left and right pointers, then recursively call the function on the new left and new right subtrees. Since every node is visited exactly once and its children are swapped, the entire tree is inverted.
- Maximum Depth of Binary Tree - There are three methods to solve this question.
    1. Recursive DFS → We use recursion to compute the maximum depth of the left and right subtrees. The base case is when the current node is None, in which case we return 0. For every other node, we return 1 + max(leftDepth, rightDepth), where 1 accounts for the current node. The recursion naturally explores every path and returns the length of the longest root-to-leaf path.
    2. Iterative BFS → We perform a level-wise traversal using a queue. Each iteration of the outer loop processes one complete level of the tree by iterating len(queue) times. For every node in the current level, we remove it from the front of the queue, process it, and add its existing left and right children to the back of the queue. After all nodes in the current level have been processed, we increment the level counter. When the queue becomes empty, all levels have been processed, and level represents the maximum depth of the tree.
    3. Iterative DFS → We perform an iterative preorder DFS using a stack that stores both the current node and its depth. We initialize the stack with the root at depth 1. In each iteration, we pop a node, update the maximum depth seen so far, and push its left and right children onto the stack with depth depth + 1. Since each node carries its own depth, we can compute the maximum depth without recursion.
    4. Diameter of Binary Tree → We use a recursive DFS that returns the height of each subtree. For every node, we recursively compute the heights of its left and right subtrees. The diameter passing through the current node is leftHeight + rightHeight, so we update a global variable with the maximum value seen so far. The DFS then returns 1 + max(leftHeight, rightHeight) so the parent can compute its own height. After traversing the entire tree, the global maximum stores the diameter of the tree.
